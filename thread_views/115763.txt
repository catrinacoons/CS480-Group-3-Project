*--- Copilot (2026-08-10 01:41:40+00:00)
`len` is a uint32_t and is assigned to a uint16_t output parameter. Even though you guard `len > UINT16_MAX`, the assignment is still an implicit narrowing conversion and can trigger compiler/MISRA warnings. Make the cast explicit after the range check.

*--- Copilot (2026-08-10 01:41:40+00:00)
`sdp_client_get_total()` validates header pulls against `buf->len`, but at this point `buf->len` also includes the continuation state bytes (not just the `frame_len` attribute list). This means malformed `frame_len` values can still cause the sequence header parsing to consume bytes from the continuation state region before being rejected by the later `frame_len < removed` check. Consider validating pulls against `frame_len` (e.g., pass `frame_len` into `sdp_client_get_total()` or parse using a bounded view) so the function never reads past the attribute list area.
