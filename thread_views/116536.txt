*--- Copilot (2026-08-17 20:42:18+00:00)
`l2cap_chan_destroy()` cancels `le_chan->rx_work` asynchronously. If the channel is destroyed from a different thread than the Bluetooth workqueue (e.g., during teardown), `rx_work` could be running concurrently and still reference a channel object that the subsequent `released()` callback may free/reuse. Consider using `k_work_cancel_sync()` when not running in the work item's queue thread (similar to the existing `rtx_work` cancel logic) to guarantee the handler is no longer executing before returning.
