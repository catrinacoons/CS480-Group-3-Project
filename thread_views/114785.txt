*--- Copilot (2026-07-28 13:24:39+00:00)
`bt_vocs_client_free_instance()` computes `CONTAINER_OF(vocs, struct bt_vocs_client, vocs)` before verifying that the passed `vocs` pointer actually belongs to the `insts[]` pool. If a caller accidentally passes a non-pooled `struct bt_vocs` with `client_instance=true`, this becomes undefined behavior. Prefer searching the pool for a matching `&vocs_inst->vocs == vocs` first (like the AICS free helper does) and only then reset/clear flags.

*--- Copilot (2026-07-28 15:01:05+00:00)
The BUSY flag check is inverted: this returns -EBUSY when the instance is *not* busy, which prevents freeing newly allocated instances (BUSY is clear right after bt_aics_client_free_instance_get()). This breaks the intended alloc-failure cleanup.

*--- Copilot (2026-07-28 15:01:06+00:00)
The BUSY flag check is inverted: this returns -EBUSY when the instance is *not* busy, which prevents freeing instances immediately after bt_vocs_client_free_instance_get() (BUSY is clear at allocation time).

*--- Copilot (2026-07-28 15:45:56+00:00)
bt_aics_client_free_instance() only checks BT_AICS_CLIENT_FLAG_BUSY with atomic_test_bit(), so it can race with other threads setting BUSY and end up resetting/freeing an instance while another operation is starting. Use atomic_test_and_set_bit() to claim BUSY during the free path, and clear it before returning.
