*--- opening post by kartben (2026-07-07 14:14:43+00:00)
When running SBOMs generated using `west spdx` through `sbomqs score`, a few easy-to-fix compliance issues get flagged, which this series of commits address:

- Missing SBOM author and tool version in SPDX Creator fields
- Missing package supplier and revision-pinned PURL on Zephyr and module packages
- Source and dependency packages lacking descriptive comments explaining their role since it's not obvious what all these `xxx-deps` and `xxx-sources` packages are and what's the difference between them...

Also, although not necessarily an NTIA compliance issue, CMake UTILITY targets (`run`, `flash`, `menuconfig`, …) were unnecessarily polluting the build SBOM so they've been dropped.

*--- Copilot (2026-07-10 14:33:50+00:00)
`has_relationship()` matches relationship types via substring search on `str(rel.relationship_type)`, which is brittle and can produce false positives/negatives depending on how `RelationshipType.__str__` is implemented. Since the rest of this test module already compares `RelationshipType` enums directly, normalize `rel_type` to a `RelationshipType` (when passed as a string) and compare with `==`.

*--- Copilot (2026-07-10 14:33:50+00:00)
`zephyr_version()` parses only MAJOR/MINOR/PATCHLEVEL, but `zspdx`’s version parsing (`walker._read_zephyr_version`) appends `EXTRAVERSION` when set. This mismatch will make the creator/tool-version assertions fail on release candidates or any build where `EXTRAVERSION` is non-empty. Parse and append `EXTRAVERSION` here too so the test matches the generator behavior.
