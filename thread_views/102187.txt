TITLE: Bluetooth: Host: Add bt_keys config flag

*--- opening post by HaavardRei (2026-01-13 13:49:02+00:00)
Adds a flag `config_flags` to the `bt_keys` struct in order to be able to detect configuration changes between firmware updates. This is needed because the `bt_keys` struct has fields which are compiled in depending on which Kconfig options are enabled, enabling the possibility of stored data being intepreted wrongly if the struct changes.

*--- HaavardRei (2026-01-13 13:52:03+00:00)
Did manual testing of the feature:

Test 1
(Pre-commit) Establish a bond (security level 4) between devices A and B with no optional kconfigs.
(Post-commit) reflash device A and reconnect --> ok (the configuration flag is added when settings are loaded).
(Post-commit) reflash device B with signing enabled --> keys are cleared.

Test 2
(Post-commit) Establish a bond (security level 4) between devices A and B with signing disabled.
(Post-commit) reflash device A with signing enabled--> keys are cleared due to non-matching configs.

The migration check assumes val[0] corresponds to cfg_version by checking if it doesn't equal STORAGE_CFG_VERSION. However, val[0] in old keys without config flags would actually be the enc_size field (which has a maximum value of 16). This logic is correct but could be clearer with a comment explaining that old keys are detected because their first byte (enc_size) will be ≤ 16, which is less than STORAGE_CFG_VERSION (17).
```suggestion
			/* This branch migrates keys stored without configuration flags to the
			 * new format, assuming that only the configuration-related fields
			 * are missing.
			 *
			 * For keys stored with configuration flags, the first byte in the
			 * serialized data is the cfg_version field, which must match
			 * STORAGE_CFG_VERSION.
			 *
			 * For older keys (without configuration flags), the first byte
			 * instead corresponds to the enc_size field. enc_size has a maximum
			 * value of 16, while STORAGE_CFG_VERSION is defined as 17. This
			 * means that for old-format keys ((uint8_t)val[0] <= 16), the check
			 * (uint8_t)val[0] != (uint8_t)STORAGE_CFG_VERSION will always be
			 * true when combined with the shorter compatible length
			 * (BT_KEYS_STORAGE_LEN_COMPAT), reliably detecting the old layout.
```
