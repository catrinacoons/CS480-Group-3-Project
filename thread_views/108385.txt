*--- Copilot (2026-05-04 06:15:02+00:00)
The option-parsing loop does not advance `i` after consuming an option/value pair. After parsing `enc <code>` or `preset <name>`, `i` remains at the value index and the next iteration reprocesses the value as if it were another option (which will either do nothing or break parsing). Increment `i` appropriately so the loop progresses to the next token after each parsed pair.

*--- Copilot (2026-05-04 06:46:12+00:00)

*--- Copilot (2026-05-04 06:46:12+00:00)
This loop runs until `i < argc`, but `argv[cap_argc]` is documented/handled as the broadcast code (see the memcpy below). As written, the broadcast code argument will be parsed as a `src_id`, and the loop variable is also later used as an index into `member_params[]`/`connected_conns[]` which can skip index 0 and exceed the connection count. Iterate only over the src_id arguments (exclude the last broadcast_code argument) and use a 0-based member index for the parameter arrays.
