This describes a different test. `arm_test_isr_handler()` never touches the FPU: it calls `k_float_disable()` on a thread other than the current one and asserts that it fails with -EINVAL, and `sup_fp_thread_entry()` then rechecks that K_FP_REGS is still set. So the case is "k_float_disable() is rejected from ISR context and leaves the target thread's FP options intact", not FP context preservation across an FPU-using interrupt.

The same block is repeated verbatim on the `#else` stub at line 327, so the one test name carries two copies of its documentation. Hoisting a single block above the `#if` would avoid that.
