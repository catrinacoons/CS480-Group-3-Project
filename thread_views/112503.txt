There are no reasons to use sys_read or sys_write. This should be just a `memcpy() + bytecpy()` for both DPRAM read and write.

```c
static inline void dpram_memcpy(void *dst, const void *src, const size_t len)
{
	const size_t m_len = ROUND_DOWN(len, sizeof(uint32_t));
 
	(void)memcpy(dst, src, m_len);

	bytecpy((uint8_t *)dst + m_len, (const uint8_t *)src + m_len, len - m_len);
}
```

*--- apr-mcnetic (2026-08-12 10:00:11+00:00)
Thanks — I'll take both points, the stray definition and the `memcpy() + bytecpy()` shape. It also resolves @tmon-nordic's concern from the earlier round, since the remainder is now written byte-exact instead of rounding the last word up.

One thing I'd like to settle before I push, though. `memcpy()` gives no guarantee about the access widths it uses, so it is only safe against the DPRAM while **both** pointers are word-aligned:

- **Write path** (`dst` = DPRAM, word-aligned): the implementation aligns `dst` first, so every store stays naturally aligned, and unaligned loads only ever hit the RAM side, which is Normal memory. Fine.
- **Read path** (`src` = DPRAM, `dst` = RAM): if the RAM destination is *not* word-aligned, a typical implementation byte-aligns `dst` first and then word-loads from a `src` that has thereby become unaligned — i.e. unaligned reads straight back at the DPRAM. That is exactly the fault this patch is meant to remove.

I could not construct a case in mainline that actually hits it: UDC buffers are `UDC_BUF_ALIGN`-aligned and OUT continuations append full-mps chunks, so `net_buf_add()` stays word-aligned. But nothing in the driver or in the UDC buffer API enforces that, and the failure mode is a hard UsageFault rather than a slow path.

Would this work for you as a compromise? It keeps your shape and the optimized copy on the path that is actually taken, and only makes the precondition explicit:

```c
/*
 * The USB DPRAM is Device memory: an unaligned half-word or word access faults
 * regardless of CCR.UNALIGN_TRP. memcpy() does not guarantee access widths, so
 * use it only while both pointers are word-aligned -- then copying the
 * word-multiple part cannot produce an unaligned DPRAM access. Anything else is
 * copied byte by byte, which Device memory always allows.
 */
static inline void dpram_memcpy(void *dst, const void *src, const size_t len)
{
	const size_t m_len = ROUND_DOWN(len, sizeof(uint32_t));

	if (!IS_ALIGNED(dst, sizeof(uint32_t)) || !IS_ALIGNED(src, sizeof(uint32_t))) {
		bytecpy(dst, src, len);
		return;
	}

	(void)memcpy(dst, src, m_len);
	/* Copy the unaligned remainder byte by byte */
	bytecpy((uint8_t *)dst + m_len, (const uint8_t *)src + m_len, len - m_len);
}
```

If you consider the branch over-engineered, I'm equally happy with your unconditional version plus the precondition documented and checked in debug builds:

```c
	__ASSERT_NO_MSG(IS_ALIGNED(dst, sizeof(uint32_t)) && IS_ALIGNED(src, sizeof(uint32_t)));
```

Just tell me which one you prefer and I'll push that.
