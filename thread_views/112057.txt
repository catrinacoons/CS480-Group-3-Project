*--- Copilot (2026-07-08 07:31:00+00:00)
SAI_KER_CK_FIELD_INIT uses a literal designated initializer `.name`, which does not expand to the struct member (e.g. `.sai_ker_ck`) and will not compile (no `name` member in struct stm32_sai_cfg). Use the macro parameter as the designated field name.

*--- Copilot (2026-07-08 07:31:01+00:00)
The `clock-names` schema is incorrect for a string-array: `enum` at the property level constrains the *entire array* rather than each item, and the block also overrides `base.yaml` without re-stating `type: string-array`. This can cause devicetree validation failures for valid multi-clock nodes. Also, because this property is now required, all existing `st,stm32-sai` nodes need `clock-names` (e.g. `dts/arm/st/h5/stm32h562.dtsi` has a `sai2` instance without it).

*--- Copilot (2026-07-08 07:31:01+00:00)
Indentation of the new `SAI2B_SEL` macro doesn’t match the surrounding `#define` alignment (tabs used elsewhere in this header). This makes the block inconsistent and harder to scan.

*--- Copilot (2026-07-08 07:31:02+00:00)
