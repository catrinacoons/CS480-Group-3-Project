TITLE: modem: cellular: on-demand neighbour cells

*--- opening post by wkhadgar (2026-07-23 22:14:19+00:00)
Today the cellular API can report the serving cell on demand, but offers no view of the neighbouring cells the modem measures around it.

This adds a `scan_neighbor_cells` driver operation and `cellular_scan_neighbor_cells()`, which measures the neighbour cells and writes them into a caller provided buffer.

The Quectel EG25-G drives the feature end to end, decoding its AT+QENG="neighbourcell" report.

The periodic timer is also rearmed when the periodic script cannot start in await dial and await registered, matching registered.

*--- wkhadgar (2026-07-27 14:37:04+00:00)
> Is this now extending the cellular driver API to direction what 3GPP standard does not offer?

The fields (EARFCN, PCI, RSRP, RSRQ) are standard 3GPP measurement quantities, until here nothing new, what's non-standard is the vendor AT to read them, and that's exactly why a typed API helps here. 

> Why does it need to be on the driver API, instead of custom scripts that can possibly run on separate CMUX channel?

`QENG` (Quectel), `%NCELLMEAS` (Nordic), `#MONI` (Telit), `+UCGED` (u-blox), all report the same thing in different ways of their own, so a custom script hands the app raw per-modem text it has to parse and redo for every vendor... The getter gives one vendor-neutral struct so consumers stay portable, and the driver already polls + parses this over its existing CMUX channel, so exposing the parsed result is cheaper than every app re-implementing it on a user pipe. I would think of it like serving-cell status, wich already belongs on the API, neighbours are nothing but a consistent extension.

*--- Copilot (2026-09-14 16:59:27+00:00)
Clearing staging only after a commit leaves partial rows behind when the periodic script times out or aborts (for example on `+CME ERROR`, which is not handled by `qeng_neighbourcell_match`). The state machine retries the periodic script, so its next empty/short scan can publish or append those stale rows as the newest measurement. Reset/discard staging at the start of each neighbour query and on failed script completion.

*--- Copilot (2026-09-14 16:59:28+00:00)
This shared API table is used by every `MODEM_CELLULAR_DEFINE_INSTANCE`, but only the EG2x-G vendor ever populates the new cache. All other generic cellular modems therefore advertise this optional operation and return `-ENODATA` forever instead of the documented `-ENOSYS` for an unsupported device. Please gate the operation on a vendor capability (or provide a vendor-specific API table) so unsupported modems remain distinguishable from supported modems that have not measured yet.

*--- Copilot (2026-09-14 16:59:28+00:00)
The new tests exercise only the generic accumulator with prebuilt cells; no test feeds an EG2x-G `+QENG: "neighbourcell ..."` response through modem chat. Consequently the new field offsets, intra/inter handling, placeholder rejection, and serving-cell filtering can all regress without detection. Extend the existing EG25-G UART-emulation coverage with representative response lines and assert the accessor output.

*--- Copilot (2026-09-14 16:59:28+00:00)
The implementation explicitly returns `-EINVAL` when either pointer is NULL, but this public API documentation omits that discrete return value. Document it so callers can distinguish invalid arguments from unavailable data.
