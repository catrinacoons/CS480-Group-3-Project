The magic number check is essential for portability across boot modes.

On platforms supporting SD card boot or external memory initialization, the noinit section may contain arbitrary patterns from previous sessions or manufacturing test data. Without the magic check, random RAM values (e.g., m_testcase_index = 0x00000002) could appear as valid test states, causing the suite to skip test cases or use uninitialized variables, leading to unpredictable failures.

The magic pattern (1 in 4 billion collision probability) reliably distinguishes cold boot from watchdog reset across all platforms.

*--- Harini-T (2026-04-13 06:43:09+00:00)
Thanks for the suggestion. The if (m_testcase_index == 0U) check is intentionally separate from the magic block because test_wdt_no_callback needs to run twice:
1. On cold boot — to install the watchdog and wait for reset
2. 2. After the first WDT reset — to detect the reset occurred and advance m_testcase_index to 1

After the WDT reset, the magic block is skipped (magic matches), but m_testcase_index is still 0 and m_state is CHECK_RESET. The separate check ensures test_wdt_no_callback is called again to complete the test case. Moving it into the magic block would break this flow.

*--- Copilot (2026-05-12 15:16:14+00:00)
WDT_TEST_MAGIC_NUMBER is defined as an untyped hex literal. Since it’s compared/stored in DATATYPE (uint32_t or uint64_t) and this repo targets a MISRA-C subset, please make the constant explicitly unsigned/typed (e.g., cast to DATATYPE or use UINT32_C/UINT64_C as appropriate) to avoid integer-conversion surprises and keep the literal width clear.

*--- Copilot (2026-05-12 15:16:14+00:00)
Cold-boot detection relies solely on m_magic != WDT_TEST_MAGIC_NUMBER. Since NOINIT can contain arbitrary data, there’s still a (small but non-zero) chance m_magic matches by coincidence and leaves other noinit variables uninitialized, causing nondeterministic test behavior. Consider strengthening the initialization condition by also validating m_state/m_testcase_index ranges (or storing a second value like ~magic) before skipping initialization.
