*--- pyhys (2025-09-02 21:05:27+00:00)
Thanks for your valid concerns, @ubieda! I fully agree that we should not add random breakout boards.

However this INA219 shield fulfills the definition perfectly fine, and the reason is the I2C connectors (NOT the pin header). These connectors are intended exactly to "attach to a board to extend its features and services for easier and modularized prototyping." The I2C connectors have four pins; GND, +3.3 Volt, I2C data and I2C clock (in that order). The physical connector is the 1.0 mm pitch JST-SH.

Adafruit calls these "Stemma QT", and has more than 50 boards supporting this interface and more than 100 sensor or actuator shields supporting this connector standard.
See https://www.adafruit.com/category/1018

Other manufacturers use other brand names for the same connector, for example Sparkfun calls it "Qwiic". https://www.sparkfun.com/special-categories/qwiic.html

Support for this shield interface was recently introduced to Zephyr. Due to the different brand names, the interface was named "zephyr_i2c", and there are already quite a few boards with this connector having that label in their devicetree files. For more details see the 4.2 release notes: https://docs.zephyrproject.org/latest/releases/release-notes-4.2.html#other-notable-changes

I think it would be great with some summary in the documentation about the supported shield interfaces (Arduino, Feather, zephyr_i2c, Microbus, Pico etc). I can take a stab at writing a few sentences for each interface, and maybe add a link to the technical requirements for each.   

Further it would be really helpful if the boards page could filter on the shield interface, so it would be possible to find shields or boards with for example the Arduino interface. For a board is the necessary information available in the device tree file, and correspondingly in the overlay file for the shield.

Any suggestion on documentation update for this particular PR?
