*--- Copilot (2026-09-17 17:00:57+00:00)
The recovery result is discarded before retrying. On Infineon, the light recovery can return `-ETIMEDOUT` when the wrapper gate or reset bits do not become usable; immediately calling `start_xfer()` after that can access an unavailable core. Abort the transfer when recovery fails instead of marking it recovered and retrying.

This issue also appears on line 1394 of the same file.

*--- Copilot (2026-09-17 17:00:57+00:00)
If this pre-CCC recovery fails, the code still submits the CCC. In particular, an Infineon hook timeout means core register access may not be safe. Check the return and leave through `error` before calling `start_xfer()`.

This issue also appears on line 2980 of the same file.

*--- Copilot (2026-09-17 17:00:58+00:00)
Continuing after `pm_resume` fails can fault: the Infineon hook returns an error when it cannot enable the peripheral clock or reopen the wrapper gate, yet the next statement accesses core registers. Propagate the failure after releasing the mutex, as the normal PM resume path already does.

*--- Copilot (2026-09-17 17:00:58+00:00)
This assigns the Infineon hooks to every `snps,designware-i3c` instance whenever any enabled Infineon node selects the Kconfig option. In a devicetree containing both an Infineon-wrapped instance and a plain DesignWare instance, the plain instance will run Infineon MMIO/clock code and fail or access unrelated registers. Select the ops per instance based on that node's compatible.

*--- Copilot (2026-09-17 17:00:58+00:00)
This readiness check occurs before taking `data->mt`. With concurrent callers, another transfer can run and leave the controller halted while this caller waits for the mutex, after which this caller starts without rechecking. Take the mutex first and perform the readiness check while holding it so the state being validated cannot change before submission.

*--- Copilot (2026-09-17 17:00:58+00:00)
This is a broadcast DISEC, so it disables interrupts, controller-role requests, and hot-join events on every addressed target—not only `newdevs`. A runtime DAA triggered by hot join will therefore silently disable IBIs previously enabled on existing targets while the driver still treats those IBIs as enabled. Limit DISEC to newly assigned targets (for example with directed CCCs), or do it only in the bus-initialization phase that already broadcasts DISEC before DAA.

*--- Copilot (2026-09-17 17:00:59+00:00)
A full reset is transparent recovery, but these writes reject all SIR/MR requests and the DAT replay below also forces `SIR_REJECT`. Any targets for which the application previously called `i3c_ibi_enable()` stop delivering IBIs after recovery, with no software state change or notification. Snapshot and restore the reject masks and per-DAT IBI bits rather than resetting them to the init defaults.

This issue also appears on line 3365 of the same file.
