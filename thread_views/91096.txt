*--- opening post by Cristib05 (2025-06-05 05:29:57+00:00)
This is a first sample of Border Router functionality that we want to implement.
Added a new application for OpenThread Border Router.

### Known issues and missing stuff in this initial implementation:
* OpenThread is not processing messages from AIL on its own context. Message queues and events signaling should be implemented.
* Newly added files do not contain a full implementation; minimum work was done at POC level as this is an experimental feature for the moment.

### Testing the implementation

The setup is very simple: An RW612 device that acts as a Border Router, an OpenThread node and a Linux host machine (used for initiating ping requests). The Border Router acts as the network leader, the other OpenThread node is a router and is also subscribing a multicast address to the BR.
For this proposed PR, testing consists in creating a network and being able to ping the BR and the OpenThread node from the Linux host.

*--- rlubos (2025-07-11 11:16:52+00:00)
`NET_EVENT_L4_CONNECTED` might not be a good choice. The thing with this event is that it will only be called when **any** of the interfaces in the system is considered to have connectivity (i.e. is up and has IP address assigned). So for example in a scenario when Thread interface connects to network first, this event would only be called then (so the iface pointer won't match). If the Ethernet/Wi-Fi interface is considered "connected" after this, the event won't be called for the second time. 

Probably better to stick to `NET_EVENT_IF_UP/DOWN` events monitoring to start/stop BR functionality, which is called for each interface separately.
