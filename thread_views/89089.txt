TITLE: Bluetooth: CSIP: Set member: Fix issue with re-registration

*--- opening post by Thalley (2025-04-25 11:38:57+00:00)
The bt_csip_set_member_register kept a counter that was not decreased when bt_csip_set_member_unregister was called. This meant that we could register and unregister CSIS, but we could not re-register once it had been unregistered.

This commit fixes this by removing the counter and instead rely on the service instance state, which also requires restoring the original service definition, as well as adding a test that would have failed with the previous version.

So there is an array
```c
		struct bt_csip_set_member_svc_inst
			*svc_insts[CONFIG_BT_CSIP_SET_MEMBER_MAX_INSTANCE_COUNT];
```

Which is used to ensure that we can register `CONFIG_BT_CSIP_SET_MEMBER_MAX_INSTANCE_COUNT` CSIS instances
Then there's the global `svc_inst` (which is also used for other tests), that is used to verify that we get an error if we attempt to register more than `CONFIG_BT_CSIP_SET_MEMBER_MAX_INSTANCE_COUNT` CSIS instances. 

I am/was tempted to create a local variable for this purposes, rather than using the global `svc_inst`; let me know if you prefer that
