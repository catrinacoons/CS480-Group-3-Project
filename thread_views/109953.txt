Continuation of #93379. Creating a new PR because cherry-picked commits needed to be squashed with some changes. Thanks to @dsseng for the support!

Add support to launch the 2nd core (CPU1) of the rp2350 from the main core (CPU0) for the Cortex-M33 CPUs using the new `rp2xxx-cpu1` and `rp2xxx-cpu1-xip` snippets (naming suggestions appreciated). The `rp2xxx-cpu1[-xip]` snippets are modeled after the [`nordic-flpr`](https://docs.zephyrproject.org/latest/snippets/nordic/nordic-flpr/README.html#).

Add support to launch the 2nd core (CPU1) of the rp2350 from the main core (CPU0) for the Cortex-M33 CPUs.

Add the rpi_pico2/rp2350a/m33/cpu1 board target that is has 256kB SRAM, gpio controller, and uart1 by default. CPU0 is responsible for launching CPU1 in a soc late init hook. When CPU0's board dts has `&cpu1`'s node with an `enable-method = "raspberrypi,pico-pcbs";` and a `cpu_enable` node with a matching compatible.

The `raspberrypi,pico-pcbs` node provides `source-memory` and `execution-memory` properties to the CPU0 board target.  

If CPU0's board dts has both `source-memory` and `execution-memory` properties in `cpu1-launcher`, CPU0 will copy CPU1's image from `source-memory` into `execution-memory` and assumes that CPU1's CONFIG_XIP=n (the default). If only `execution-memory` is present, it is assumed that CPU1's CONFIG_XIP=y. This is modeled after a combination of the [Analog Devices max78002evkit](https://docs.zephyrproject.org/latest/boards/adi/max78002evkit/doc/index.html) and Nordic's [vpr launcher driver](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/misc/nordic_vpr_launcher/nordic_vpr_launcher.c).

**Note:** Running both CPU0 and CPU1 XIP is much slower than running CPU1 from SRAM because of XIP cache contention between the 2 cores. However, it may be necessary if CPU1's image does not fit in SRAM.

Although CPU1 is a board variant, this PR does not yet support using it as an independent target like the `cpuflpr`. This would require some custom sysbuild.cmake magic as seen [here](https://github.com/zephyrproject-rtos/zephyr/blob/main/soc/nordic/sysbuild.cmake).

The nrf54L15's has a [VPR peripheral ](https://docs.nordicsemi.com/bundle/ps_nrf54L15/page/vpr.html) at `0x5004C000` (Secure) or `0x4004C000` (non-secure). The nrf54lxx's dtsi file creates a [`cpuflpr_vpr` devicetree node](https://github.com/zephyrproject-rtos/zephyr/blob/ab92232cfcd1362ee481ba06197fda7d6613aff5/dts/vendor/nordic/nrf54l_05_10_15.dtsi#L173) with the `nordic,nrf-vpr-coprocessor` compatible string, which has the following properties in its bindings file:

The `execution-memory` and `source-memory` are used by the [vpr_launcher driver](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/misc/nordic_vpr_launcher/nordic_vpr_launcher.c) to manage the `cpuflpr`'s image location (if necessary) and launch the `cpuflpr`. The `cpuflpr_vpr` devicetree node is enabled and its execution/source memory is set in the `nordic-flpr` snippets. The `nordic-flpr` snippets are applied to the main sysbuild applications in the samples so the primary CPU (`cpuapp`) can launch the secondary CPU (`cpuflpr`) with knowledge of where the `cpuflpr` image is.

The rp2350 doesn't have a CPU1 launcher peripheral with a dedicated *address range*, but CPU0 still needs to know where CPU1's image is located and where it executes from. The `zephyr,code-cpu1-partition` and `zephyr,sram-cpu1-partition` chosen properties are devicetree hacks to provide equivalent information to the `cpuflpr_vpr`'s `execution-memory` and `source-memory` properties.

@dsseng did start with a binding and driver similar to the `cpuflpr_vpr`, but that was rejected since the rp2350 doesn't have a cpu1 launcher hardware device. 
https://github.com/zephyrproject-rtos/zephyr/pull/93379#discussion_r2264822824

The `zephyr,[code|sram]-cpu1-partition` chosen properties are unsustainable, especially since other boards use it (See [`lpcxpresso55s69/lpc55s69/cpu0`](https://github.com/zephyrproject-rtos/zephyr/blob/43609419c8070c2c3f45f60d7cb3d61d38a42a47/boards/nxp/lpcxpresso55s69/lpcxpresso55s69_lpc55s69_cpu0.dts#L42-L43)) and variations of it (See `zephyr,code-rv32-partition` in the [`max78002evkit/max78002/m4`](https://github.com/zephyrproject-rtos/zephyr/blob/43609419c8070c2c3f45f60d7cb3d61d38a42a47/boards/adi/max78002evkit/max78002evkit_max78002_m4.dts#L26) and `zephyr,code-m7-partition` in the [`frdm_imxrt1186/mimxrt1186/cm33`](https://github.com/zephyrproject-rtos/zephyr/blob/43609419c8070c2c3f45f60d7cb3d61d38a42a47/boards/nxp/frdm_imxrt1186/frdm_imxrt1186_mimxrt1186_cm33.dts#L25)).
