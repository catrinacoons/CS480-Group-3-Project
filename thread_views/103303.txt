I have been able to get to the following so far in this branch:

Build coap server with oscore:
```
west build -b qemu_x86 samples/net/coap/coap_server/ -T sample.net.sockets.coap_server.oscore
```

Then start the server. 

Run shell script to test it with default compiled in values:

```
bash samples/net/coap/test-oscore.sh
```

This runs a few requests against the sample server. 

The config for coap client looks like this:
```
# Master Secret (same for client + server)
master_secret,hex,"0102030405060708090a0b0c0d0e0f10"

# Master Salt (optional, but if you use it, must match server)
master_salt,hex,"9e7ca92223786340"

# Sender ID (THIS device, i.e. the client)
sender_id,ascii,"client"

# Recipient ID (remote peer, i.e. the server)
recipient_id,ascii,"server"

# Replay window (usually 32)
replay_window,integer,32

# AEAD algorithm (default is 10 = AES-CCM-16-64-128, but be explicit)
aead_alg,integer,10

# HKDF algorithm (default is -10 = direct+HKDF-SHA-256, optional but can be explicit)
hkdf_alg,integer,-10
```

So far so good.

*--- Copilot (2026-02-02 02:26:51+00:00)
For a "check" helper, returning `-ENOENT` when the option is absent forces all callers to special-case the “no option” path even though it’s not an error condition. Consider returning `0` with `*suppress = false` when the option is absent, and reserve negative returns for actual parse/validation failures (e.g., invalid length). This makes the API easier to consume and less error-prone.
```suggestion
		return (ret < 0) ? ret : 0;
```

*--- Copilot (2026-02-02 02:26:52+00:00)
The sequence increment is atomic, but the returned token buffer is a single shared static array that is written on every call. Concurrent calls can race and overwrite the same buffer contents, causing callers to observe corrupted/duplicated tokens. Prefer an API that writes into a caller-provided buffer (or return a thread-local buffer), or protect the write with a lock if the API contract allows.
```suggestion
	static _Thread_local uint8_t token[COAP_TOKEN_MAX_LEN];
```

Update the README to match the actual default behavior (or adjust the sample default to match the documented behavior).

By default, the sample server requires OSCORE for all requests (``require_oscore = true``).
