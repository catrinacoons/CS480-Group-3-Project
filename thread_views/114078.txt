TITLE: scripts: ci: check_compliance: add option to run checks in parallel

*--- opening post by kartben (2026-07-20 13:25:46+00:00)
The compliance checks currently run strictly one after the other. Most of the total runtime is spent in the Kconfig-based checks, each of which parses a full Kconfig tree on its own.

Add a -p/--parallel [N] option that runs the checks in a pool of N worker processes (one per CPU by default). Each check runs in its own process, which also isolates the environment variable mutations and module imports the Kconfig checks perform. The Kconfig-based checks are scheduled first so the slowest checks are not left running alone at the end.

Enable the new option in the compliance workflow, where the runtime of the Kconfig checks now roughly amounts to the single slowest check instead of the sum of all of them.

Full compliance check runs **2.5-3x faster** on my Mac (12 parallel processes) ; I think the performance improvement is less noticeable on Linux. **EDIT:**  just tested, on the same commit range, **Linux is roughly 5x faster** :) (16 parallel workers on this machine)

*--- Copilot (2026-07-24 09:44:05+00:00)
The PR description says each check runs in its own process to isolate environment-variable mutations and imports, but `multiprocessing.Pool` workers are reused by default, so a single worker process may execute multiple checks. That can still allow cross-check leakage (notably from Kconfig checks that mutate `os.environ`), and makes check behavior dependent on how tasks get scheduled to workers.
